# ADR-0009 成批矛盾用审阅页裁决

状态：accepted
日期：2026-10-11

背景：
ADR-0007 把需用户裁决的矛盾收成冲突表，写进当次会话日志，并规定不新开文档类型。930 一夜无眠的一次自检列出二十余条对不上的说法。长文清单难逐条裁决，导出的标注若只有编号和笔记，agent 改文档时还得回头翻原文。用户要求：修矛盾和同类 bug 时，给出一份可双击打开的交互页面，能看上下文、分类、写评论，并导出一份 agent 能直接读的文件。

决策：
1. 需裁决的矛盾或剧情 bug 达到 3 条时，复制 `docs/templates/review-board.html` 为 `docs/reviews/YYYY-MM-DD-短主题.html`。agent 只填页面里的 JSON 数据岛。1–2 条仍在对话里问，写入会话日志。四轮骨架审阅仍走叙事路径.md §6.1。
2. 用户在页面里逐条标「要改 / 不用改 / 以后再改」并写评论，导出 `{review_id}-标注.json` 放回 `docs/reviews/`。导出的每条带标题、分类、出处、原文摘录、建议改法和评论。
3. agent 只读该 JSON 再改文件。`yes` 按评论改，评论为空则按建议改法，两者都空或不够执行就停下问；评论与建议冲突时以评论为准。`no` 不改正文。`later` 记待办。`unread` 与未出现的条目不改。只改该条点名的文件。
4. 仍有未裁决条目，或「要改」尚未落地，自检不通过。会话日志只留路径、裁决和落地文件。操作细则的单一权威是叙事路径.md §6.4。

备选方案：
- 继续只在会话日志里写冲突表：条数一多就难逐条裁，也被这次的使用否决。
- 页面壳与清单 JSON 分开，每次打开壳再选文件：少一次复制，多一次打开步骤，用户选择双击一份 HTML。
- 用命令把 JSON 生成成 HTML：多一个构建步骤，用户选择数据写进同一份可双击的页面。
- 四轮骨架审阅也改成这种网页：会把「一轮一问」的小包重新堆成一次看完，维持 ADR-0007 的四轮。

后果：
CLAUDE.md 阶段 2、阶段 5 与 §8 各留一行指针。实例初始化时不预填 `docs/reviews/`，`review-board.html` 随模板保留。ADR-0007 的「冲突表写入会话日志、不新开文档类型」只继续适用于 1–2 条。
