# ADR-0006 母本预置参考校验脚本

状态：accepted
日期：2026-10-04

背景：
框架明确「用数据审计对抗，不以自查代替」（叙事路径.md §3.1），但母本不带校验脚本、最早也要阶段 3 才落地——阶段 2 全部图门禁（死路/孤岛/结局可达）在此之前只能靠 agent 手工遍历，恰是框架宣布不信的那种自查；开放世界的图结构红线（死链=0、环秩≥2、割点）手工几乎查不动。已有两个实装项目各自写过同类脚本，新项目再重写属重复成本。

决策：
母本预置 `/tests/story-validation/validate.js`（Node、无依赖）：vm 沙箱加载 .js 对象字面量（与运行引擎选型无关）→ 图遍历与 schema 校验——死路/死链/孤岛/不可达结局/无法抵达结局（死循环）/跨文件重复 ID/文本重复/变量四字段闭环/未声明变量/值域越界/伏笔台账 × 行内注释双向对账；`--gen-index` 从 lore 卡生成 index.json（消灭索引双写）。附 `fixtures/mini` 迷你样例作冒烟自检。阶段 2 验证方式改为直接跑脚本；阶段 3 只在标注的「扩展点」追加项目 schema 与路径专属审计。新增约定：入口节点 ID 为 `start`（可达性检查起点）。

备选方案：
- 维持各项目阶段 3 自建脚本：阶段 2 空窗期只能手工遍历，被否。
- 只维护校验清单不写脚本：无执行保证，等于把「自查代替审计」制度化，被否。

后果：
CLAUDE.md 新增 §7「常用命令」（校验/冒烟自检/报告存档），阶段 2 门禁验证方式与阶段 3 产出要求同步改写。项目改用 ESM/模块导入加载剧情时只改 loadStory() 一处（已标注）。脚本经 fixture 正反向验证：合法样例全绿；注入死链、未声明变量均被抓出（孤岛作为死链的衍生也验证）。
