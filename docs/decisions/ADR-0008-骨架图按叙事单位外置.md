# ADR-0008 骨架图按叙事单位外置

状态：accepted
日期：2026-10-06

背景：
workflow-v2.9 把阶段 2 骨架图草案写入 `03-story-blueprint.md`，当时为了不新增文件类型。骨架里是节拍、职责、遭遇和装配后的节点剧情，和蓝图要冻结的结构合同（章/区功能、结局路由、变量索引）挤在同一文件里，章或区域一多就会臃肿。ADR-0007 否决的是按 NPC / 机制 / 地点拆文档（一次返工要改三处），没有要求细节剧情必须留在蓝图里。

决策：
1. `03-story-blueprint.md` 只做结构合同，模板见 templates.md §13。不写节拍正文、职责长表、遭遇卡、装配图。
2. 细节剧情放入 `docs/skeleton/`，按叙事单位一份：固定分支与混合型公共脊柱用 `chN-<短名>.md`，开放世界区域与混合型扩展区用 `region-<名>.md`。跨章、跨区的边只写在 `index.md`。格式与分工见叙事路径.md §6.3。
3. 四轮审阅仍按 ADR-0007 执行，落盘位置改为对应骨架文件。终幕成段正文留到阶段 4；实体长述在 lore 卡；规则全表的主文件在概念圣经或 lore，蓝图与骨架只引用编号。
4. 区域方案的场景清单改为一行指针，装配图只在该区骨架文件里写一次。

备选方案：
- 继续把骨架图全写进蓝图：结构合同与细节剧情绑在同一份阅读里，被否。
- 全游戏只建一份 `skeleton.md`：多章或多区域之后同样臃肿，被否。
- 每张遭遇卡单独一个文件：返工散落到多文件，和 ADR-0007 要避免的同步成本同类，被否。
- 按 NPC / 机制 / 地点拆：ADR-0007 已否决，维持。

后果：
CLAUDE.md 阶段 2 产出与 §8 文件结构改为蓝图 + `docs/skeleton/`。叙事路径.md §6.3 为骨架文件的单一权威；自检通读清单加入该目录。实例初始化时不预填骨架，阶段 2 再按章或区域创建。
