# ADR-0004 剧情文件从 JSON 改为 .js 对象字面量

状态：accepted
日期：2026-10-04

背景：
硬规则 1 原定「剧情全部放 JSON 配置」。但两个已完成项目（尸潮笔记、规则怪谈）的剧情文件实为 .js 对象字面量，且核心协作经验依赖 JS 才能表达：伏笔行内注释（埋设/回收/设计意图如「真·红鲱鱼」）、选择影响注释（数值+叙事后果+结局判据锚点）、区域文件头结构图、动态封路函数路由。JSON 不支持注释，与「AI 实时记录伏笔、在剧情文件中注释选择影响」的实践直接冲突；强行外置到独立文档会造成注释与节点分离、跨文件维护成本。

决策：
硬规则 1 改为「剧情与引擎分离」：剧情全部放独立 .js 剧情文件（对象字面量，按章/幕/区域分文件，向 storyData 合并或模块导入由阶段 3 定），引擎只解析与运行；行内注释与少量路由函数合法，但数据形态必须仍可被校验脚本加载（路由函数返回值须为节点 ID 且有静态兜底）。variables/endings/foreshadow 同步 .js 化。templates.md §6 定义三种行内注释规范：文件头结构图、伏笔标注、选择影响标注。

备选方案：
- 纯 JSON + `_note` 字段 + 独立台账：校验最简、引擎无关，但失去行内自由注释与函数路由，两个项目验证过的注释实践无法落地。
- JSON 默认 + .js 逃生舱（阶段 3 按需裁决切换）：两套规范并存、校验脚本分叉，复杂度最高。

后果：
templates.md §6-§8 schema 重写为 .js；最小校验脚本改为加载 .js 而非 JSON.parse；跨引擎移植性略降（可接受——技术栈在阶段 3 锁定后本就不要求跨引擎）。
